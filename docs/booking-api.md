# Онлайн-запись VESPERA — контракт API

Серверная часть записи без внешних сервисов: справочники в `src/lib/studio.ts`,
броней — файл `data/bookings.json`, вся логика времени — в `src/lib/booking.ts`.

- Базовый префикс: `/api/booking`
- Формат: JSON, `Content-Type: application/json`
- Часовой пояс: `Europe/Moscow` (UTC+3 круглый год, перехода на летнее время нет)
- Аутентификации нет: бронь подтверждается кодом, а не аккаунтом
- Все ответы отдаются с `cache-control: no-store`

## Правила слотов

| Правило | Значение |
| --- | --- |
| Окно приёма | 12:00–22:00, услуга должна **закончиться** не позже 22:00 |
| Сетка стартов | шаг 30 минут от 12:00 |
| Длительность | берётся из справочника услуги, не с клиента |
| Минимальный запас | 2 часа от текущего момента (нельзя записаться «через 20 минут») |
| Горизонт записи | 90 дней вперёд |
| Рабочие дни | у каждого мастера свои; день недели — по московской дате |
| Занятость | слот мастера блокируется на всю длительность услуги; отменённые брони не блокируют |

Дата всегда строка `YYYY-MM-DD`, время — `HH:mm`. Календарная проверка строгая:
`2026-02-30` — ошибка, а не «2 марта».

## GET /api/booking/availability

Свободные слоты мастера на дату для конкретной услуги.

**Параметры (query, все обязательны):**

| Имя | Тип | Описание |
| --- | --- | --- |
| `serviceId` | string | `id` или `slug` услуги |
| `masterId` | string | `id` или `slug` мастера |
| `date` | string | `YYYY-MM-DD` |

```bash
curl "http://localhost:3000/api/booking/availability?serviceId=svc-skin&masterId=ms-alisa&date=2026-12-03"
```

**200 — обычный ответ.** В списке все стартовые точки сетки, включая занятые:
интерфейсу полезно показать «занято», а не дырку.

Слоты «ближе двух часов» помечены `available: false` — кроме случая, когда запрос пришёл
с валидной админской cookie `vespera_admin` (ручная запись из консоли).

```json
{
  "date": "2026-12-03",
  "serviceId": "svc-skin",
  "masterId": "ms-alisa",
  "durationMin": 90,
  "timezone": "Europe/Moscow",
  "slots": [
    { "time": "12:00", "available": true },
    { "time": "12:30", "available": false },
    { "time": "13:00", "available": true }
  ]
}
```

**200 — причина вместо слотов.** Несуществующая услуга/мастер или нерабочий день —
это не ошибка ввода, поэтому `200`, пустой список и `reason`:

| `reason` | Когда |
| --- | --- |
| `unknown_service` | услуги нет в справочнике |
| `unknown_master` | мастера нет в справочнике |
| `master_not_assigned` | мастер не выполняет эту услугу |
| `day_off` | мастер не работает в этот день недели |
| `date_in_past` | дата уже прошла по Москве |
| `date_out_of_range` | дата дальше горизонта записи (90 дней) |

В ответах с `reason: "unknown_service"` поле `durationMin` приходит как `null`:
длительность неизвестной услуги сервер выдумывать не будет.

```json
{
  "date": "2026-12-06",
  "serviceId": "svc-skin",
  "masterId": "ms-alisa",
  "durationMin": 90,
  "timezone": "Europe/Moscow",
  "slots": [],
  "reason": "day_off"
}
```

**400 — параметры не прошли валидацию.**

```json
{
  "ok": false,
  "error": "invalid_request",
  "message": "Укажите дату в формате YYYY-MM-DD",
  "details": {
    "fields": [{ "field": "date", "message": "Укажите дату в формате YYYY-MM-DD" }]
  }
}
```

## POST /api/booking

Создание брони. Сервер сам подставляет цену и длительность и сам проверяет занятость.

**Тело запроса:**

| Поле | Тип | Обяз. | Правила |
| --- | --- | --- | --- |
| `serviceId` | string | да | `id` или `slug` услуги |
| `masterId` | string | да | `id` или `slug` мастера |
| `date` | string | да | `YYYY-MM-DD`, не в прошлом, ≤ 90 дней вперёд |
| `time` | string | да | `HH:mm`, старт из сетки 30 минут, окно 12:00–22:00 |
| `name` | string | да | 2–60 символов после trim |
| `phone` | string | да | российский номер: `+7…`, `8…` или 10 цифр; нормализуется к `+7XXXXXXXXXX` |
| `email` | string | нет | валидный email, ≤ 120; пустая строка = не указан |
| `comment` | string | нет | ≤ 500; пустая строка = не указан |
| `honeypot` | string | нет | устаревшее имя ловушки, принимается до переименования в UI |
| `vespera_hp` | string | нет | поле-ловушка со «случайным» именем; заполнено → «успех» без записи |
| `formStartedAt` | number | нет | `Date.now()` при монтировании формы; сабмит быстрее 1.5 c → «успех» без записи |

Поле `company` сервер **не** проверяет и не считает признаком бота: браузерные
автозаполнители заполняют его сами, и настоящие заявки из-за этого пропадали.
`formStartedAt` при отсутствии или мусоре тоже не считается признаком бота.

Поля `price`/`duration`/`status` с клиента **игнорируются**, даже если придут в теле.

```bash
curl -X POST "http://localhost:3000/api/booking" \
  -H "Content-Type: application/json" \
  -d '{
    "serviceId": "svc-skin",
    "masterId": "ms-alisa",
    "date": "2026-12-03",
    "time": "13:00",
    "name": "Анна",
    "phone": "8 (999) 123-45-67",
    "email": "anna@example.com",
    "comment": "Первый раз"
  }'
```

**201 — бронь создана.**

```json
{
  "ok": true,
  "code": "VSP-7K4M",
  "booking": {
    "code": "VSP-7K4M",
    "status": "confirmed",
    "date": "2026-12-03",
    "time": "13:00",
    "durationMin": 90,
    "priceRub": 12000,
    "name": "Анна",
    "phone": "+7 9•• ••• 45 67",
    "service": { "id": "svc-skin", "slug": "skin-ritual", "name": "Ритуал кожи" },
    "master": { "id": "ms-alisa", "slug": "alisa-vetrova", "name": "Алиса Ветрова", "role": "кожа, протоколы ухода" },
    "createdAt": "2026-11-15T09:12:44.512Z",
    "email": "anna@example.com",
    "comment": "Первый раз"
  }
}
```

**200 — повторная отправка той же заявки.** Если совпали телефон, услуга, мастер, дата
и время, возвращается уже созданная бронь: `duplicate: true`, тот же `code`.
Дубликат не создаётся, и никаких чужих персональных данных в ответе нет — только
код, маскированный телефон, услуга, мастер и параметры слота:

```json
{
  "ok": true,
  "duplicate": true,
  "code": "VSP-7K4M",
  "booking": {
    "code": "VSP-7K4M",
    "status": "confirmed",
    "date": "2026-12-03",
    "time": "13:00",
    "durationMin": 90,
    "priceRub": 12000,
    "phone": "+7 9•• ••• 45 67",
    "service": { "id": "svc-skin", "slug": "skin-ritual", "name": "Ритуал кожи" },
    "master": { "id": "ms-alisa", "slug": "alisa-vetrova", "name": "Алиса Ветрова", "role": "кожа, протоколы ухода" }
  }
}
```

Ни `name`, ни `email`, ни `comment` в этой ветке нет: знать телефон и слот недостаточно,
чтобы прочитать чужую заявку. Полные данные отдаёт только `GET /api/booking/{code}`
(тоже без email и комментария).

**400 — ошибка валидации.**

```json
{
  "ok": false,
  "error": "invalid_request",
  "message": "Имя должно быть не короче 2 символов",
  "details": {
    "fields": [{ "field": "name", "message": "Имя должно быть не короче 2 символов" }]
  }
}
```

Другие 400: `unknown_service`, `unknown_master`, `master_not_assigned`, `day_off`,
`invalid_slot` (время вне окна/не по сетке), `slot_in_past` (меньше 2 часов до начала
или дата прошла), `date_out_of_range`.

**409 — слот заняли между выбором и подтверждением.**

```json
{
  "ok": false,
  "error": "slot_taken",
  "message": "Это время уже занято. Выберите другой слот"
}
```

**429 — больше 5 заявок с одного IP за 10 минут.** В заголовке `Retry-After` — секунды
до следующей попытки.

```json
{
  "ok": false,
  "error": "rate_limited",
  "message": "Слишком много заявок с этого адреса. Попробуйте через 4 мин.",
  "details": { "retryAfterSec": 213 }
}
```

**Антибот.** Заполненное поле-ловушка (`vespera_hp`, либо устаревшее `honeypot`) или
сабмит быстрее 1.5 c (`formStartedAt`) дают `201` с правдоподобным кодом и полностью
такой же формой ответа, как у настоящей брони, но запись не создаётся. Поле `company`
игнорируется: его заполняют автозаполнители браузера, а не люди.

## GET /api/booking/{code}

Бронь для экрана подтверждения. Email и комментарий не отдаются, телефон замаскирован.

```bash
curl "http://localhost:3000/api/booking/VSP-7K4M"
```

**200:**

```json
{
  "ok": true,
  "timezone": "Europe/Moscow",
  "booking": {
    "code": "VSP-7K4M",
    "status": "confirmed",
    "date": "2026-12-03",
    "time": "13:00",
    "durationMin": 90,
    "priceRub": 12000,
    "name": "Анна",
    "phone": "+7 9•• ••• 45 67",
    "service": { "id": "svc-skin", "slug": "skin-ritual", "name": "Ритуал кожи" },
    "master": { "id": "ms-alisa", "slug": "alisa-vetrova", "name": "Алиса Ветрова", "role": "кожа, протоколы ухода" },
    "createdAt": "2026-11-15T09:12:44.512Z"
  }
}
```

**400** — код не похож на `VSP-XXXX`:

```json
{ "ok": false, "error": "invalid_request", "message": "Код брони выглядит так: VSP-7K4M" }
```

**404:**

```json
{ "ok": false, "error": "not_found", "message": "Бронь с таким кодом не найдена" }
```

Код — единственный доступ к брони, поэтому перебор ограничен: 60 запросов с одного IP
за 10 минут, дальше `429 rate_limited` с `Retry-After`.

## Модель данных

`data/bookings.json` (создаётся при первой записи, в git не попадает):

```json
{
  "version": 1,
  "bookings": [
    {
      "code": "VSP-7K4M",
      "status": "confirmed",
      "serviceId": "svc-k3m9x2qp",
      "serviceName": "Ритуал кожи",
      "serviceSlug": "skin-ritual",
      "masterId": "ms-eva",
      "masterName": "Ева Ким",
      "masterSlug": "eva-kim",
      "date": "2026-12-03",
      "time": "13:00",
      "durationMin": 90,
      "priceRub": 12000,
      "name": "Анна",
      "phone": "+79991234567",
      "email": "anna@example.com",
      "comment": "Первый раз",
      "createdAt": "2026-11-15T09:12:44.512Z"
    }
  ]
}
```

- `serviceName`/`serviceSlug`/`masterName`/`masterSlug` — **снапшоты** названий на момент
  записи. Каталог редактируемый, услуги и мастера удаляются физически, поэтому имя в брони
  не зависит от текущего справочника: если записи в каталоге больше нет, оно берётся отсюда.
  При удалении услуги/мастера сервер дописывает снапшоты во все связанные брони.

- `status`: `confirmed` | `completed` | `cancelled` | `no_show`; слот держит только
  `confirmed`. Статусы меняет админка — см. `docs/admin-api.md`.
- `note`, `createdBy`, `history` — внутренние поля админки; публичный API их не отдаёт.
- `durationMin` и `priceRub` — снимок справочника на момент записи; измените цену в
  `studio.ts`, старые брони останутся с прежней.
- Файл читается терпимо: неизвестные записи отбрасываются, дубликаты кодов схлопываются.

## Надёжность записи

- Все изменения идут через `mutateBookings` — очередь на promise-цепочке, поэтому
  одновременные запросы не могут прочитать одно состояние и оба записать.
- Проверка занятости и уникальности кода выполняется **внутри** этой критической секции.
- Запись атомарная: временный файл в каталоге данных + `rename`.
- Перед перезаписью предыдущая валидная версия сохраняется в `data/bookings.json.bak`.
- Если `bookings.json` повреждён, чтение берёт `.bak`; если и он битый — пустой список.
  Первая успешная запись восстановит основной файл.
- Ошибка записи → `500 server_error`, клиент может повторить: код брони не выдаётся,
  дубликат не создаётся.

## Ограничения

- Нет отмены/переноса брони через API (статус `cancelled` поддержан в модели данных).
- Нет уведомлений: email/телефон только сохраняются.
- Нет платёжной системы и внешней БД.
- Rate limit in-memory и сбрасывается при перезапуске процесса: для одного инстанса
  этого достаточно, за балансировщиком нужен общий счётчик.
- IP клиента определяется в таком порядке: `x-vercel-forwarded-for` (его ставит Vercel,
  клиент не контролирует) → `x-real-ip` → **последний** адрес `x-forwarded-for` (его
  дописывает ближайший прокси) → `unknown`. Первый адрес `x-forwarded-for` намеренно
  не используется: клиент присылает его сам и может подделать лимит.
- Запись брони живёт в файле `data/bookings.json` или в Postgres — см. `docs/storage.md`.
- Коды `VSP-XXXX` (24 символа без похожих друг на друга, ~331 000 комбинаций) —
  защита от случайного подбора, но не от целенаправленного перебора при утечке IP-лимитов.

## Как очистить тестовые данные

```bash
# остановить dev-сервер не обязательно
rm -rf data/bookings.json data/bookings.json.bak
```

PowerShell:

```powershell
Remove-Item data/bookings.json, data/bookings.json.bak -ErrorAction SilentlyContinue
```

Каталог `data/` вернётся сам при первой записи. Хранилище можно увести в другое место
переменной окружения `VESPERA_DATA_DIR` (например, для e2e-прогонов):

```bash
VESPERA_DATA_DIR=.tmp-e2e npm run dev
```
